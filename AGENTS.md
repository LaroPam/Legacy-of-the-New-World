# Инструкции для Codex: «Наследие нового мира 2.0»

Прочитай `docs/PROJECT_VISION.md`, `docs/REWARD_POLICY.md`, `docs/CURRENT_STATE_AND_ROADMAP.md`, `docs/VALIDATION_AND_RELEASE.md` до любых значимых изменений.

## 1. Зачем существует этот проект

Это **долгосрочный авторский квестбук-приключение** для двух игроков, Максима и Юры, на локальном сервере Minecraft **Forge 1.20.1** с FTB Quests и KubeJS. Он **не должен быть прежде всего учебником по модам**. Квестбук направляет прогрессию и делает мир интереснее: исследования, секреты, необязательные приключения, редкие мобы, структуры, боссы, необычные механики, создание техники, испытания и крупные цели. Подробные объяснения нужны, когда механика трудная, но не вместо игры.

Сервер запускается только во время совместной игры. Прогресс должен сохраняться после выключения, повторного входа, смены сессий и обновления версии. Нельзя предполагать, что сервер постоянно работает.

## 2. Источник истины, данные и прогресс

- Работай **только с реально переданным архивом/репозиторием и установленными версиями модов**; не придумывай ID предметов, достижений, мобов, структур, рецептов и событий.
- Сначала инвентаризуй `config/ftbquests/quests/`, `kubejs/`, ресурсы, зависимости и моды. Исторические отчёты — подсказки, но не доказательства.
- **Не изменяй и не переиспользуй существующие Quest ID, Task ID и Reward ID** без согласования и явной миграции. Сохраняй пользовательский прогресс. Новым сущностям — уникальные новые ID.
  - **Согласовано для Alpha 43 (2026-10-22):** прогресс существующего мира не критичен. ID сохраняются, где квест остаётся по смыслу; при перестройке глав разрешено удалять квесты и выдавать новые ID без миграций. Повторно использовать старый ID для другого смысла по-прежнему нельзя. См. `docs/ALPHA43_PLAN.md`.
- ID FTB Quests 2001.4.22 — только `0000000000000002`…`7FFFFFFFFFFFFFFF`: ID с первой цифрой 8–F FTB не читает
  (объект получает случайный ID при каждой загрузке, ссылка на квест роняет сервер). 2026-10-23 такие ID
  перенумерованы, таблица — `reviews/id_remap_alpha43.json`.
- Не удаляй квесты, награды, описания, ресурсы или взаимосвязи незаметно. Если исправление меняет фактический смысл уже выполненного квеста, опиши эффект на старые сохранения.
- Не обещай сохранение/пересчёт прогресса без проверки реальных правил FTB Quests.
- Не перезаписывай оригинальный ZIP. Создавай репозиторий, отдельные изменения и новый релиз, оставляя базовую версию доступной.

## 3. Качество квестов

- Гибридная прогрессия: содержательный основной путь и **широкая свобода** самостоятельных побочных веток. Не связывай несвязанные приключения жёсткими обязательными зависимостями.
- Каждый квест должен иметь ясный игровой смысл, необычное действие/открытие или значимый шаг прогрессии. Не гонись за количеством. 1000+ квестов допустимы, **только если они качественные**.
- Не засоряй главы дублирующими Item Task, повторяющимися убийствами без вариаций, ванильной рутиной и заданиями, автоматически выполняющимися сразу пачкой одним действием.
- **Автоматические проверки — приоритет**. Условия должны подтверждать именно заявленное действие. `player_interacted_with_entity` — это взаимодействие, не обязательно успешное кормление/приручение; `player_generates_container_loot` — генерация лута, а не извлечение предмета; наличие блока в инвентаре — не построенный механизм. Эти различия всегда учитывай.
- Не используй ручные галочки для значимых квестов с наградами. Ручное подтверждение допустимо лишь как явно обозначенное исключение для совсем незначимых целей, без существенной награды. Если автоматика невозможна, предложи другой объективно проверяемый замысел.
- Разбиение сложного механизма на содержательные промежуточные этапы полезно; не превращай каждое действие в формальную проверку предмета.
- Для коллективных заданий проверяй, может ли Максим сделать часть действий, а Юра — другую, и как настроен FTB Teams. Не выдавай индивидуальную проверку за командную.
- Тон описаний: живой, понятный, преимущественно русский; интерес, открытие, умеренный юмор. Иногда делай необязательные забавные квесты с именами Максим и Юра.
- Не добавляй Twilight Forest: игроки проходили его неоднократно, он им неинтересен.
- Lost Souls 2 — ориентир по масштабу, ухоженности и связанности квестов, **не шаблон для копирования**.

## 4. Визуальные правила

- Прозрачный фон графа; **никаких декоративных баннеров**.
  - **Согласовано 2026-10-23:** автор разрешил фоны — у каждой главы свой полноэкранный фон 16:9 через свойство
    темы `background` с селектором главы (FTB берёт фон по выбранной главе, см. `docs/BACKGROUND_PROMPTS.md`).
    Фон лежит под линиями и значками и должен оставаться тёмным и спокойным. Картинки глав (chapter images)
    как подложки не используются: они рисуются поверх линий. Баннеры по-прежнему не добавляются. Чисто, аккуратно, атмосферно, читаемо внутри настоящего интерфейса FTB Quests.
- Компактные, визуально связанные графы; логичные группы, пространство между узлами; не допускай пересечения линий, проведения линий через другие значки, наложений и бессистемных разрывов.
- Значки тематические и проверенные. **Согласовано 2026-10-23:** все квесты — круглые медальоны одного вида, тип
  виден по рамке (рисунки автора `art/frames/`, обработка `tools/quest_frames.py`): `step` — обычный шаг;
  `expedition` — экспедиция; `milestone` — веха, особое достижение; `trial` — опасное испытание; `tech` — техника и
  стройка; `boss` — босс, кульминация; `home` — дом, люди, торговля. Значок предмета — `icon_scale` 0.75, чтобы
  помещался в рамку. Тип выбирай по смыслу шага; это **принцип, а не безусловное правило для каждого узла**.
- Линии связей мягкие (`dependency_soft.png`), без стрелок FTB.
- Не предполагай, что сгенерированные концепт-изображения точно соответствуют реальному экрану Minecraft. Опирайся на SNBT и в идеале игровую проверку.
- **Не добавляй звуки** за выполнение квестов: пользователь от них отказался.

## 5. Награды

- Следуй `docs/REWARD_POLICY.md`: щедро, тематично, справедливо, без скачков прогрессии. За боссов лучше редкий тематический предмет, чем гора обычных ресурсов.
- Важно качество награды **на данном этапе**, а не только XP. После сложного квеста приз должен ощущаться заслуженным. Награды есть и за простые содержательные квесты; избегай пустых или формальных призов.
- Если награды выдаются персонально, одно уникальное оружие на игрока, а не три одинаковых экземпляра. Отдельно проверь фактические настройки выдачи в FTB Quests.
- Не выдавай предмет, автоматически завершающий ещё не пройденное задание на коллекционирование; не подменяй смысл поиска бесплатной выдачей.
- **Согласовано** развитие Alpha 43 как балансный проход по 92 спорным наградам Alpha 42 с правом улучшать сомнительные предложения (например, не заменять все редкие артефакты на обычные изумруды). Сверяй каждый новый ID по JAR, логике прогрессии и теме. Пользователь уже дал общее согласие на этот проход.

## 6. Процесс разработки

1. Перед изменениями: инвентаризация, точный счёт квестов/задач/наград, список модов, SHA256 исходного ZIP, `git init` и базовый коммит (с разрешения пользователя, без перезаписи существующей истории).
2. Прежде чем править: сформулируй задачу и критерии приёмки. Используй минимальный проверяемый diff, не массовую замену regex по SNBT без проверки вложенных структур.
3. Реализуй скрипты статических тестов; прогоняй их после каждой группы правок. См. `docs/VALIDATION_AND_RELEASE.md`.
4. Держи отдельный **лог изменений**: файл, квест, прежнее значение, новое значение, причина, метод проверки, риски.
5. Для каждого релиза: полный архив, патч относительно объявленной базы, отчёт, результат проверок, неизвестные риски. Архивы должны соответствовать исходникам репозитория.
6. Не утверждай, что игровой тест пройден, если реально не запускались клиент и сервер Minecraft. Статический аудит ≠ успешная игровая проверка.
7. Если есть сомнение — уточни только критически важное, остальные разумные решения принимай самостоятельно в рамках утверждённых принципов.
