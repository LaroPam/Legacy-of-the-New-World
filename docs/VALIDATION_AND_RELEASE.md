# Проверка и выпуск (Alpha 43+)

## Откуда берётся книга

Источник истины — `src/chapters/*.yaml`, по файлу на главу. Игровые файлы
`config/ftbquests/quests/chapters/*.snbt` **генерируются** и вручную не правятся:

```
python tools/questbook.py build   # YAML → SNBT
python tools/questbook.py check   # SNBT совпадает со свежей сборкой
```

Формат источника описан в начале `tools/questbook.py`. Коротко: у квеста есть читаемый `key`,
зависимости пишутся ключами (`deps: [first_camp]` или `глава/ключ`), ID новых квестов, задач и
наград генерируются детерминированно из ключа. Старые квесты хранят свой прежний `id`.
Награда `type: book` создаёт подписанную книгу (`minecraft:written_book`) с текстом страниц.

Нестандартные условия пишутся прямо в квесте: задача `type: criteria` с одним из сокращений
(`kill`, `placed`, `bred`, `tamed`, `trade`, `loot`, `ride`, `effect`, `used_item`, `used_on_block`,
`crafted`, `obtain`, `consumed`, `in_structure_tick`, `granted`) или с `any_of`/`all_of`/`criteria`.
Сборка создаёт достижение `kubejs/data/nasledie/advancements/q/<глава>/<ключ>.json`; эта папка
целиком генерируется. Группы глав — `src/chapter_groups.yaml`, ссылки на квесты других глав —
`links:` в главе. Теги структур и биомов лежат в `kubejs/data/nasledie/tags/`.

События модов без достижений (найм в Recruits/Workers) засчитывает
`kubejs/startup_scripts/nasledie_events.js`: он выдаёт достижения `nasledie:events/...`.
Стартовые скрипты KubeJS загружаются только при запуске игры — после обновления нужен полный перезапуск.

Схемы глав для проверки раскладки: `python tools/preview.py ПАПКА [глава ...] --jars ПАПКА_С_JAR`
(положение, формы, значки и линии реальные; шрифты и рамки — нет).

Если квесты правились в игре через режим редактирования FTB Quests, такие правки нужно
перенести в YAML, иначе следующая сборка их затрёт.

## Валидатор

```
python tools/validate.py [--report file.json] [--strict]
```

Ошибки (CI красный):
- SNBT не совпадает с источниками; формат и уникальность ID; несуществующие зависимости и циклы;
- пересечения значков и линий графа; неизвестная форма квеста; квест без задач;
- ID предмета, существа, структуры, биома или достижения отсутствует в установленных модах
  (`references/registry.json`);
- награда выдаёт предмет, который является целью другого квеста (Item Task или
  `inventory_changed` в достижении); одинаковый предмет несколько раз в наградах одного квеста;
- ручная галочка с предметной наградой (книга-запись дневника допускается);
- ресурсы достижений KubeJS и текстуры форм.

Предупреждения: слишком длинные описания (похоже на инструкцию), технические слова в тексте,
одинаковые условия разных задач, преобладающий значок, очень длинные линии.

`references/known_issues.json` — ошибки, унаследованные от Alpha 42. Alpha 43 обязана довести
этот список до пустого; новые ошибки всегда валят проверку.

## Индекс модов

`references/registry.json` (ID) и `references/names_ru.json` (русские названия) строятся из JAR сборки:

```
python tools/build_registry.py ПАПКА_С_JAR --vanilla-ru ru_ru.json
```

Источник JAR — публичная папка автора на Яндекс.Диске; недоступные оттуда файлы брались с Modrinth
с проверкой SHA256 по `references/mod_catalog.json`. Индекс статический: он ловит опечатки, но не
доказывает поведение в игре.

## Выпуск

1. `python -m unittest discover -s tests`, `node --test tests/factory_trials.test.cjs`,
   `python tools/validate.py --strict`, `python tools/apply_palettes.py --check`.
2. Архив для установки: папки `config/ftbquests/` и `kubejs/` целиком.
3. Установка: на обоих компьютерах (игра по сети через «Открыть для сети» + VPN) заменить
   `config/ftbquests/quests/chapters/` целиком (старые главы удалить, иначе останутся лишние) и
   скопировать `kubejs/` поверх. Перезапустить игру полностью.
4. Игровой тест по списку проверок релиза. Статическая проверка ≠ игровой тест.
