# Статический визуальный обзор квестбука

`tools/render_review.py` создаёт автономную страницу сравнения всех глав и прозрачные SVG «до/после». Источник «до» — точный коммит Alpha 42 `f68124fb33597aa13b4b6a8dd8c6dde7c879b188`; источник «после» — файлы рабочего дерева в момент запуска, включая ещё не закоммиченные изменения.

Это **схема данных SNBT**, а не скриншот Minecraft, эмулятор интерфейса FTB Quests или игровой тест. Программа читает репозиторий и пишет только в выбранную папку отчёта. Квесты и история Git не меняются.

## Получение отчёта

Запустите из корня репозитория Python с установленным `ftb-snbt-lib`:

```bash
python tools/render_review.py \
  --baseline f68124fb33597aa13b4b6a8dd8c6dde7c879b188 \
  --output reports/visual
```

В текущей облачной среде готовый интерпретатор находится по пути `/workspace/.onboarding/legacy-venv/bin/python`. При переносе используйте окружение с зависимостями проекта, а не этот абсолютный путь.

Откройте `reports/visual/index.html` в браузере. Сервер, интернет и JavaScript-библиотеки не нужны. HTML содержит все данные и схемы и может быть передан одним файлом. Отдельные схемы находятся в `reports/visual/<имя_файла_главы>/before.svg` и `after.svg`. `manifest.json` фиксирует базовый коммит, текущий HEAD, хеши SNBT и общие границы пары схем. Отчёт необходимо пересоздать после изменения исходных файлов.

## Что можно проверить

- Все главы доступны через список. В каждой паре используются общие границы координат и одинаковый масштаб, поэтому «после» не становится искусственно компактнее за счёт независимой подгонки.
- Координаты узлов берутся непосредственно из `x` и `y`; одна единица SNBT равна 64 пикселям при 100%. Относительный размер узла следует `size`. Зависимости показаны прямыми стрелками от предшественника к зависимому квесту без автоматической перекладки графа.
- Золотой контур означает `optional: false`, голубой — `optional: true`. Это только содержимое поля; обязательность прохождения в игре зависит также от настроек FTB Quests. Оранжевое пунктирное кольцо отмечает любое изменение записи квеста, включая текст, координаты, задачи или награды.
- Номера узлов одинаковы в паре; нажмите на узел или выберите квест из списка, чтобы сравнить полные заголовки, описания, ID значков, формы, зависимости, задачи и награды. Поиск работает по названию, Quest ID и значку. Есть фильтр изменённых записей и перечень изменённых полей.
- Кнопки масштаба действуют на обе схемы. По умолчанию прокрутка синхронна. Кнопка «К выбранному узлу» центрирует выбранный квест. Подписи можно скрыть, чтобы оценить геометрию. Стрелки и пересечения намеренно не исправляются отчётом.
- Все поля задач, наград и квеста доступны в раскрываемых блоках. Настройки главы показываются отдельно и не теряются, даже если не имеют визуального представления.

## Что требует проверки в игре

Номера заменяют значки предметов: отчёт не рисует придуманные предметные текстуры. Рамки форм условны, часть форм показана кругом; точные изображения пользовательских форм, хитбоксы, рамки состояний, размеры шрифтов и многострочные заголовки отличаются от FTB Quests. Подписи на схеме — вспомогательные и не обещают соответствия режиму отображения названий в игре.

Скрытые зависимости показаны пунктиром для аудита. Межглавные связи, `quest_links`, декоративные изображения и состояние выполнения игрока не рисуются. Прозрачность экспортированных SVG не подтверждает прозрачность интерфейса в Minecraft. Проверка реального вида главы должна выполняться на установленной версии FTB Quests с ресурсами сборки и с обоими игроками.

После статической оценки отдельно проверяются доступность узлов, поиск и подсказки, фактические текстуры значков, пересечения в игровом масштабе, командный зачёт, выдача наград и сохранение прогресса после перезапуска. Ни одна из этих игровых проверок не считается выполненной только по HTML или SVG.
