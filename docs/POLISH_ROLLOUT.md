## Дополнение автора: ветки с результатом

Автор дополнительно потребовал меньше разрозненных веток, последовательное развитие
внутри каждой и явную конечную цель. Новые квесты разрешены там, где они помогают
достичь этой цели; добавление ради количества исключено. Приоритет теперь — структура
приключения и практическое применение механик, а затем окончательная компоновка.

В Create путь должен приводить к работающему производству или полезному инженерному
результату, а не заканчиваться изготовлением одиночного блока. Сначала используются
существующие проверяемые цели: например, три десерта из одного дозатора подтверждаются
достижением мода и могут завершать полноценный путь производства еды. Получение предмета
не будет выдаваться за проверку всей линии. Специальные испытания не превращаются
в обязательные препятствия для основного производства.

## Исправление «Караула солнечной рощи»

В двух достижениях заменены отсутствующие типы существ:

| Критерий | Было | Стало |
|---|---|---|
| `fury` | `mowziesmobs:umvuthana_fury` | `mowziesmobs:umvuthana_raptor`, `{mask:0}` |
| `fear` | `mowziesmobs:umvuthana_fear` | `mowziesmobs:umvuthana`, `{mask:1}` |

Доказательства из точного JAR: `reviews/grove_watch_fix_evidence.json` и
`reviews/mowzie_entity_evidence.json`. Raptor задаёт FURY; перечисление масок содержит
FURY под индексом 0 и FEAR под индексом 1; EntityUmvuthana сохраняет индекс в целочисленном
поле `mask`. У обычного воина бывают разные маски, поэтому одной замены типа недостаточно.
Зачёт за любого обычного воина вместо нужной маски не допускается.

Оба пути достижений, имена критериев, Quest ID, Task ID и Reward ID сохранены. Завершённый
прогресс не сбрасывается этим патчем; гарантировать поведение обновлённого мира без теста
нельзя. Прошлые убийства не восстанавливаются задним числом: для незавершённых условий
нужны новые победы над соответствующими противниками. Командный зачёт требует игрового теста.

Статический отчёт после правки: 0 ошибок изменений, 439 исходных предупреждений,

### Сохранённый этап: шесть глав с новой структурой

В `reviews/branch_plans.json` записаны маршруты пролога, хозяйства, поселения, торговли,
путешествий и Create. Все 102 квеста этих глав отредактированы по отдельности; с эталоном

| Глава | Конечных узлов раньше | Сейчас | Итоговые направления |
|---|---:|---:|---|
| Пролог | 2 | 1 | Подготовка к первой вылазке |
| Дом | 6 | 4 | Общий ужин, полный огород, тёплый дом, походные припасы |

| Путешествия | 8 | 3 | Небесная башня, подземная башня, морозное подземелье |
| Create | 10 | 7 | Производство десертов, мобильная мастерская, энергия, изобретения и короткие опыты |

Конечный узел — графовая метрика, а не оценка качества. В Create паровой двигатель
завершает энергетический проект, после него остаётся отдельное применение — лавовое
погружение. Зависимость погружения от десертов устранена. Рельсовое происшествие честно
требует поезд, хотя предыдущая мобильная машина использует вагонетку.

Пищевой маршрут: колесо и передача → пресс → жернова → обработка потоком → миксер и
нагрев → жидкостная сеть → три десерта из одного дозатора. Точные рецепты и код финального
события сохранены в `reviews/create_production_evidence.json`. Промежуточное достижение
обработки потоком подтверждает обработку материала вообще; рецепт теста дан как полезное
применение. Сам финал действительно проверяет выпуск всех трёх продуктов одним блоком.
Код Create хранит три отметки продукции и владельца в данных блока; успешное сохранение
и командный зачёт на вашем сервере ещё предстоит проверить в игре.

Последние проверки: 23 теста прошли, статический отчёт без ошибок, 342 исходных предупреждения,
9 категорий непроверенного. В шести новых главах нет найденных дефектов текста и геометрии.
Все исходные 478 Quest ID, 504 Task ID и 978 Reward ID сохранены; награды и задачи не менялись.
