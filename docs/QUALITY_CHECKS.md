# Статические проверки оформления

Инструменты используют Python 3.10+ и `tools/requirements.txt`. Установка в отдельное окружение:

```bash
python3 -m venv .venv
.venv/bin/pip install -r tools/requirements.txt
.venv/bin/python -m unittest discover -s tests -v
.venv/bin/python tools/quality.py --report reports/quality.json
.venv/bin/python tools/render_review.py --output reports/visual
```

В облачной среде готовый интерпретатор: `/workspace/.onboarding/legacy-venv/bin/python`.
Для данных проверки используется полный commit SHA, а не движущаяся ветка.

## Защита этого этапа

По умолчанию разрешены только поля оформления `nasledie_defense`: `title`, `description`,
`icon`, `x`, `y`, `shape`, `size`. Остальные 17 глав должны побайтно совпадать с Alpha 42.
Все ID, порядок квестов, тела задач/наград, зависимости, optional, настройки прогрессии,
JSON условий, тема и PNG защищены. Числовые типы SNBT также сравниваются.

Проверяются синтаксис, повторные JSON-ключи, ID, циклы/цели зависимостей, собственные достижения,
ресурсы форм, одинаковые условия, служебный текст и геометрия. Число разобранных JSON здесь 73:
исторический `references/mod_catalog.json` не входит в игровые входные файлы валидатора.

Известные исходные недостатки отражаются предупреждениями. Новые или ухудшенные проблемы
эталона — ошибки. Для приёмки эталона дополнительно требуется ноль замечаний по его тексту
и геометрии; одной проверки отсутствия регрессий недостаточно.
Код возврата: 0 — нет ошибок сохранности/регрессий, 1 — ошибки, 2 — ошибка вызова или чтения.
Нулевой код не означает, что весь старый квестбук качественен или пройден игровой тест.

17 тестов намеренно меняют награды, цели, типы чисел, ID, зависимости, ресурс,
другую главу и координаты, чтобы доказать работу запретов. Положительный тест разрешает только
оформление. Отдельно проверяются цикл, повтор JSON-ключа, пересечение и близость линии к узлу.

## Значки и семантика

`reviews/semantic_inventory.json` содержит все исходные квесты, полные условия из доступных
точных JAR и сохранённые замечания аудиторов. Статусы:

- `mismatch` — конкретное несоответствие с объяснением;
- `supported_by_objective` — значок совпадает с предметом цели или значком достижения мода;
- `review` — нужно редакторское решение, а не автоматическая ошибка по сходству слов.

Повторяющийся значок — сигнал для просмотра разных задач, не запрет сам по себе.
Совпадение с иконкой достижения не заменяет анализ смысла. Список предметных моделей в JAR
не выдаётся за реестр зарегистрированных предметов. `--registry` принимает отдельно подготовленный
снимок реестров с `evidence.source`, `evidence.sha256` и массивами `items`, `entities` и т. д.;
без него внешние ID остаются явно непроверенными. Не подставлять список моделей вместо реестра.

`tools/audit_project.py` воспроизводит исходный контекст аудита из Git и ранее скачанных JAR.
`tools/fetch_mod_evidence.py --retry-failures` повторяет только неуспешные загрузки, сохраняя
результаты успешных. Новые артефакты проверяются SHA256 и ZIP CRC; обход проверки запрещён.

## Ограничения

Геометрия — прямые связи и диски значков; интерфейс FTB, переносы названий и реальный масштаб
проверяются в Minecraft. Условие зачёта, доступность реестров при запуске, личные/командные
награды и сохранение мира требуют отдельного игрового прогона. Исходные ошибки условий
не исправляются под видом оформления и должны оставаться в отчёте до согласования.
