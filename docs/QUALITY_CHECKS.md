# Статические проверки квестбука

Инструменты используют Python 3.10+, `tools/requirements.txt` и Node.js 18+
(в CI — Node 22). Node не требует установки пакетов. Установка и обязательные проверки:

```bash
python3 -m venv .venv
.venv/bin/pip install -r tools/requirements.txt
.venv/bin/python -m unittest discover -s tests -v
.venv/bin/python tools/quality.py --report reports/quality.json
node --test tests/factory_trials.test.cjs
.venv/bin/python tools/apply_polish.py --check
.venv/bin/python tools/apply_palettes.py --check
```

Текущий результат: 46 Python-тестов и 24 Node-сценария прошли; статический отчёт —
0 ошибок, 0 предупреждений, 10 неизвестных категорий. Minecraft не запускался.
Node выполняет скрипт на моделях API, а не на Rhino/Forge/Create.

В облачной среде готовый интерпретатор: `/workspace/.onboarding/legacy-venv/bin/python`.
Для данных проверки используется полный commit SHA, а не движущаяся ветка.

## Защита этого этапа

После утверждения эталона разрешены поля оформления глав, перечисленных в
`reviews/polish_scope.json`: `title`, `description`, `icon`, `x`, `y`, `shape`, `size`.
Без этого файла инструмент сохраняет исходный режим одной эталонной главы.
Все ID, порядок квестов, тела задач/наград, optional, настройки прогрессии и PNG
исходных квестов защищены. Для темы разрешён единственный точный SHA256 в file_fixes. Зависимости могут отличаться только на точные согласованные значения из
`quest_fixes`; JSON условий — только на точные хеши из `file_fixes`.
Числовые типы SNBT также сравниваются. Любое последующее отклонение от разрешённой правки
снова считается ошибкой. `completed_chapters` требует чистоты текста и геометрии уже
переработанных глав, даже если оставшийся дефект был в исходной версии.

Проверяются синтаксис, повторные JSON-ключи, ID, циклы/цели зависимостей, собственные достижения,
ресурсы форм, одинаковые условия, служебный текст и геометрия. Число разобранных игровых JSON сейчас 80:
исторический `references/mod_catalog.json` не входит в игровые входные файлы валидатора.

С 2026-10-22 `quest_additions` в `reviews/polish_scope.json` содержит точные SNBT
новых квестов и причины добавления. Существующий ID нельзя объявить новым; сохраняются
все старые записи, а новые задачи, награды, зависимости и порядок сравниваются с
объявлением с учётом типов SNBT. Оформление новых квестов воспроизводится из дизайна.
`file_additions` разрешает только новые собственные JSON достижений с точным SHA256;
отсутствие/изменение файла, замена прежнего файла и исполняемый код так не допускаются.
`apply_polish.py --check` воспроизводит также новые квесты. Исходный семантический
аудит по-прежнему относится к 478 старым квестам; пять новых описаны отдельно в
`reviews/expedition_action_evidence.json` и `docs/EXPEDITION_ACTIONS.md`. Ещё два
производственных финала описаны в `reviews/factory_trial_evidence.json` и
`docs/FACTORY_TRIALS.md`. Игровые входные данные содержат 80 JSON и 19 SNBT.

`script_additions` разрешает только `kubejs/server_scripts/nasledie_factory_trials.js`
с точным SHA256, причиной и ссылками на тесты/доказательства. Отсутствие файла, подмена
байтов, замена прежнего файла, иной путь или неполное объявление блокируются.
`minecraft:impossible` не имеет естественного события: два разных таких достижения
различаются по ID команды/API. Два задания на один такой ID по-прежнему считаются
дублем. Для обычных и смешанных условий сравнение содержимого сохранено.
Отдельная неизвестная категория напоминает о непроверенном Java-мосте наблюдателя.

После замечания автора добавлен `dominant_quest_icon`: глава от 8 квестов, где один
явно заданный предмет занимает больше 40% значков (минимум 4), требует пересмотра.
Небольшие тематические группы допустимы; значки, которые FTB берёт из задач, здесь
не оцениваются. Для `completed_chapters` это ошибка даже при наличии дефекта в базе.
Порог помогает найти однообразие, но не доказывает уместность каждого значка или
удобство реального интерфейса. `completed_chapters` означает область строгих статических
проверок, а не художественную приёмку глав автором.

Известные исходные недостатки отражаются предупреждениями. Новые или ухудшенные проблемы
эталона — ошибки. Для приёмки эталона дополнительно требуется ноль замечаний по его тексту
и геометрии; одной проверки отсутствия регрессий недостаточно.
Код возврата: 0 — нет ошибок сохранности/регрессий, 1 — ошибки, 2 — ошибка вызова или чтения.
Нулевой код не означает, что весь старый квестбук качественен или пройден игровой тест.

Python-тесты проверяют защиту данных: намеренно меняют награды, цели, типы чисел, ID, зависимости, ресурс,
другую главу и координаты, чтобы доказать работу запретов. Положительный тест разрешает только
оформление. Отдельно проверяются цикл, повтор JSON-ключа, пересечение и близость линии к узлу.
Тест исходного дефекта условий проверяет, что успешная защита данных не скрывает блокер прохождения.

`reviews/mowzie_entity_evidence.json` содержит регистрации EntityHandler точного Mowzie 1.8.2
и SHA256 JAR. По этим данным валидатор обнаруживает два отсутствующих типа существ в условиях
«Караула солнечной рощи» в исходной версии. После разрешённого исправления они больше не
попадают в текущий `gameplay_blockers`; причина и точный diff сохранены в журнале.
Вновь добавленное такое условие считается ошибкой. Это ограниченная проверка конкретного
мода, не полный снимок реестров работающей сборки. `release_ready` всегда `false`:
этот инструмент не проверяет игру и обновление сохранений.

## Значки и семантика

`reviews/semantic_inventory.json` содержит все исходные квесты, полные условия из доступных
точных JAR и сохранённые замечания аудиторов. Статусы:

- `mismatch` — конкретное несоответствие с объяснением;
- `supported_by_objective` — значок совпадает с предметом цели или значком достижения мода;
- `review` — нужно редакторское решение, а не автоматическая ошибка по сходству слов.

Повторяющийся значок — сигнал для просмотра разных задач, не запрет сам по себе.
Совпадение с иконкой достижения не заменяет анализ смысла. Список предметных моделей в JAR
не выдаётся за реестр зарегистрированных предметов. `--registry` принимает отдельно подготовленный
снимок реестров с `evidence.source`, `evidence.sha256` и массивами `items`, `entities` и т. д.;
без него внешние ID остаются явно непроверенными. Не подставлять список моделей вместо реестра.

`tools/audit_project.py` воспроизводит исходный контекст аудита из Git и ранее скачанных JAR.
`tools/editorial_context.py` выводит условия выбранной главы из этого сохранённого контекста.
`tools/plan_branches.py` переводит индивидуально заданные маршруты из `reviews/branch_plans.json`
в точные разрешённые зависимости и координаты, проверяя, что каждый квест указан ровно один раз.
`tools/apply_polish.py` воспроизводит редакцию и сохраняет прежние/новые значения по каждому ID
в `reviews/changes/`; `--check` проверяет совпадение исходников с дизайном без записи.
`tools/fetch_mod_evidence.py --retry-failures` повторяет только неуспешные загрузки, сохраняя
результаты успешных. Новые артефакты проверяются SHA256 и ZIP CRC; обход проверки запрещён.

## Исторические визуальные инструменты и архив образца

По указанию автора HTML и браузерные проверки сейчас не обновляются и не входят
в обязательный цикл. Ниже описаны сохранённые инструменты предыдущего этапа.

После генерации HTML необязательная проверка отчёта запускается командой
`python3 tools/smoke_visual.py`. Нужны Playwright и Chromium; в облачной среде они доступны
системному Python. Проверяются выбор главы/квеста, фильтр, подписи, масштаб и отсутствие
ошибок JavaScript. Результат с SHA256 документа — `reports/browser_smoke.json`.
Снимок `reports/visual/reference-comparison.png` показывает HTML-схему, не Minecraft.
Этот браузерный шаг не включён в обязательную проверку GitHub Actions.

`python3 tools/package_reference.py` создаёт `reports/reference-preview.zip`, патч только
эталонной главы относительно объявленной базы и манифест SHA256. В ZIP входят глава,
пояснение ограничений и сведения об источнике. При сборке проверяются CRC и побайтное
совпадение главы с рабочим файлом. Это образец для оценки, не полный игровой релиз.

## Ограничения

Геометрия — прямые связи и диски значков; интерфейс FTB, переносы названий и реальный масштаб
проверяются в Minecraft. Условие зачёта, доступность реестров при запуске, личные/командные
награды и сохранение мира требуют отдельного игрового прогона. Исходные ошибки условий
не исправляются под видом оформления и должны оставаться в отчёте до согласования.

## Палитры и текущий комплект

`tools/apply_palettes.py --check` проверяет обязательный `[*]`, точные ID всех 18 глав,
полноту четырёх состояний, свойства, цвета и совпадение с индивидуальными палитрами.
Ещё 4 теста ловят игнорируемый заголовок, ошибочный селектор-тег, повтор секции и подмену
ID главы. Они входят в текущие 46 Python-тестов. Исходники FTB и хеши записаны в theme_source_evidence.json.
Встроенные формы FTB не требуют дубликатов текстур в kubejs; собственные требуют.

Общая команда воспроизводимости — `tools/apply_polish.py --check`; историческая
`apply_reference.py --check` больше не является проверкой текущей главы охоты.
Уже существовавший корень без поля dependencies тоже может получить точную разрешённую
связь; отсутствие исходного поля не подменяется пустым массивом при защите данных.

После новых правок отчёт quality содержит SHA256 всех входных игровых файлов.
`tools/package_candidate.py` требует совпадения этих хешей, сохранённых в Git исходников,
собирает полный комплект квестбука и патч относительно базы. ZIP проверяется CRC и побайтно,
патч применяется во временной копии базы и сравнивается со всеми рабочими игровыми файлами.
Результаты: reports/questbook-candidate.zip, .patch и -manifest.json. Это кандидат
для тестовой установки по docs/CANDIDATE_INSTALL.md, не игровой релиз.

Браузерный smoke дополнен переключением всех 18 глав и 72 вариантов цвета/состояния.
Он проверяет HTML, а не FTB Quests. Исторический reference-preview.zip больше не является
актуальным комплектом; его скрипт оставлен для истории эталона.
